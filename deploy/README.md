# Deploy targets

Each folder here holds everything specific to one deploy target. The build copies
`deploy/$DEPLOY_TARGET/public/` (default `cloudflare`) into the root of the output;
anything outside `public/` stays out of the build.

## cloudflare

Cloudflare Pages, deployed by its git integration from the `production` branch.

- `public/_headers`, `public/_routes.json`: Pages config.
- Pages Functions live in `functions/` at the repo root, where Pages requires them.

## wisp

[wisp.place](https://wisp.place), which serves sites stored as records in an atproto repo.

```sh
HOST_NAME=wisp.impro.social OAUTH_PUBLIC_JWK=... OAUTH_ASSERTION_URL=https://impro.social/oauth/assertion DEPLOY_TARGET=wisp npm run build
npx wispctl deploy <handle> --path build --site impro
```

- `public/_redirects`: SPA fallback, plus 404s for missing assets.
- wisp can't run functions, so confidential OAuth signs assertions via the Cloudflare
  endpoint (`OAUTH_ASSERTION_URL`), which must list the site's origin in its
  `OAUTH_CROSS_ORIGIN_CLIENTS` env var. Omit `OAUTH_PUBLIC_JWK` for a public client.
- Response headers come from a `place.wisp.settings` record, not a file in the build.
  Its contents are in `settings.json`; write them with
  `APP_PW=... node deploy/wisp/put-settings.js <did> <site>`.
